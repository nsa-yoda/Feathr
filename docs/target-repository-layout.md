# Target Repository Layout

Codex may refine filenames, but preserve the separation of responsibilities and update this document if the final tree differs materially.

```text
.
├── README.md
├── ARCHITECTURE.md
├── AGENTS.md
├── pyproject.toml
├── uv.lock
├── Dockerfile

├── Makefile

├── .specify/
├── .agents/skills/                 # generated by Spec Kit Codex integration
├── docs/
│   ├── adr/
│   ├── architecture/
│   ├── operations/
│   ├── ai-workflow-log.md
│   └── requirements-traceability.md
├── specs/                          # Spec Kit feature artifacts
├── src/event_platform/
│   ├── main.py
│   ├── api/
│   │   ├── middleware/
│   │   ├── routes/
│   │   │   ├── events.py
│   │   │   ├── stats.py
│   │   │   ├── search.py
│   │   │   └── health.py

│   ├── domain/
│   ├── queue/
│   ├── storage/
│   ├── search/

│   └── cli/
├── tests/
│   ├── unit/
│   ├── integration/
│   └── failure/
├── frontend/
│   ├── src/
│   ├── package.json
│   └── Dockerfile
├── postman/
│   ├── Distributed Event Processing Platform.postman_collection.json
│   └── Local Docker.postman_environment.json
└── scripts/
    ├── bootstrap-speckit.sh
    └── smoke.sh
```

Dependency direction should remain approximately: `api` and `worker` orchestration -> `core`/`domain` contracts -> infrastructure adapters. Search projection orchestration stays under `search`; do not let route modules become service locators for raw database clients.
