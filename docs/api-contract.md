# API Contract Guardrails

Final OpenAPI generated by FastAPI is authoritative, but these semantics must hold.

## Implemented in Feature 001

`GET /health/live` returns `200`, `application/json`, and `{"status":"alive"}` without dependency calls. `GET /health/ready` reports core readiness and returns `503` when Mongo, queue, or the persistence worker cannot make progress. `GET /health/components` reports fixed safe states for Mongo, Elasticsearch, Redis, queue, persistence worker, and search projector. `GET /metrics` returns Prometheus text with bounded labels. `/openapi.json` and `/docs` are available for API discovery. Each HTTP response includes a canonical UUID in `X-Request-ID` (a valid bounded inbound UUID is preserved) and a server-generated `X-Operation-ID`.

The foundation returns `application/problem+json` for framework HTTP errors, request validation, and unexpected exceptions. The body has exactly `type`, `title`, `status`, `detail`, `instance`, `error_code`, and `request_id`; its `status` and `request_id` agree with the HTTP status and response header. `instance` contains only the path. Unknown routes use `route_not_found` and status 404; validation uses `request_validation_failed` and status 422; unexpected failures use `internal_error` and status 500. Details are fixed safe summaries, and required HTTP headers such as `Allow` on 405 are preserved. The test-only validation and unexpected-error routes are not production endpoints. See [the Feature 001 HTTP contract](../specs/001-platform-foundation/contracts/http-foundation.md).

The endpoint contracts below are implemented by Feature 015 and remain guardrails for later dependency wiring.

## POST /events

Success: `202 Accepted`.

Response includes `event_id`, `status: queued`, `request_id`, and a statement/field that does not imply durable completion.

Validation failures: 422 or a consistently chosen 400/422 problem response. Event queue saturation: 503 + `Retry-After`. Rate-limited requests normally wait for an atomic leaky-bucket release slot; full admission-backlog overflow returns 429 + `Retry-After`, `RateLimit-Limit`, `RateLimit-Remaining`, and `RateLimit-Reset`. Limited successful responses include the three `RateLimit-*` headers, and queued responses identify the leaky-bucket policy. Health and metrics are exempt by default; Redis failures use the conservative bounded local limiter and emit a structured degraded event.

## GET /events

Optional filters: event type, inclusive UTC `start`/`end`, user ID, and exact source URL. `limit` defaults to 50 and is bounded to 200. The opaque, signed, versioned cursor contains only the last timestamp and event UUID; its signature is also bound to the active filters. Return canonical Mongo event items, the effective limit, `request_id`, and `next_cursor` when more exist. Mongo is the canonical read source, so results may temporarily precede Elasticsearch projections.

## GET /events/stats

Bucket: `hour|day|week` (default `hour`). Both `start` and `end` may be omitted for the previous 24-hour UTC window; supplying only one is invalid. Explicit ranges are inclusive UTC timestamps bounded to 366 days. `week` buckets start on Monday. The response includes the effective `start`, `end`, fixed `timezone: UTC`, ordered nonzero counts grouped by bucket and event type, and `request_id`. Analytics returns at most 10,000 grouped points and rejects larger result sets rather than returning partial counts. The canonical Mongo aggregation has a finite 5-second `maxTimeMS` deadline to bound high-cardinality request lifetime. It reads canonical Mongo state through `$match` → `$dateTrunc`/`$group` → stable sort and returns safe 422/503 problem responses.

## GET /events/search

Required safe query string; optional stable filters may be added. Search only uses application-generated Elasticsearch DSL. Bounded page size and opaque `search_after` cursor.

## GET /events/stats/realtime

Lightweight rolling UTC summary. `window_minutes` is optional and bounded to 1..60
(default 5). The response contains `schema_version`, `total_events`, sorted
`by_event_type`, `generated_at`, inclusive `window_start`/`window_end`, and
`request_id`. `X-Cache` is `HIT`, `MISS`, or `BYPASS`; Redis is a disposable
cache and Mongo remains the canonical source. Invalid windows return 422 and
Mongo failures return a safe retryable 503.

## Health/ops

The service provides `/health/live`, `/health/ready`, `/health/components`, and `/metrics`, plus a read-only reviewer operations/status API sufficient for the UI without leaking event bodies/secrets.

## Errors

Use `application/problem+json` fields:

- `type`
- `title`
- `status`
- `detail`
- `instance`
- `error_code`
- `request_id`

Dependency-specific raw exceptions must never be returned to clients.

## Security boundary

The service rejects request bodies larger than the configured
`EVENT_PLATFORM_REQUEST_BODY_MAX_BYTES` limit before route parsing. The default
is 1 MiB and the accepted range is 1 KiB–16 MiB. Query/search strings, page
sizes, UTC ranges, metadata, and signed opaque cursors are bounded by their
typed contracts. The raw query string is limited by
`EVENT_PLATFORM_REQUEST_QUERY_MAX_BYTES` (8 KiB by default, 256 bytes–64 KiB)
before route parsing. Oversized bodies return `413` with `error_code`
`request_body_too_large`; oversized raw queries return `414` with
`request_query_too_large`; invalid input returns the normal safe `422` problem.

CORS is exact-origin only and disabled when
`EVENT_PLATFORM_CORS_ALLOWED_ORIGIN` is unset. Forwarded client IP headers are
ignored by default. API responses include browser security headers and never
include raw dependency errors, stack traces, credentials, or request bodies.
