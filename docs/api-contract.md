# API Contract Guardrails

Final OpenAPI generated by FastAPI is authoritative, but these semantics must hold.

## POST /events

Success: `202 Accepted`.

Response includes `event_id`, `status: queued`, `request_id`, and a statement/field that does not imply durable completion.

Validation failures: 422 or a consistently chosen 400/422 problem response. Queue saturation: 503 + `Retry-After`. Rate limit: 429 + `Retry-After`.

## GET /events

Optional filters: event type, start/end, user ID, exact source URL. Bounded `limit`; opaque `cursor`. Return items + `next_cursor` when more exist.

## GET /events/stats

Bucket: `hour|day|week`. Bounded range. Counts grouped by bucket and event type.

## GET /events/search

Required safe query string; optional stable filters may be added. Search only uses application-generated Elasticsearch DSL. Bounded page size and opaque `search_after` cursor.

## GET /events/stats/realtime

Lightweight configured rolling window summary. Include cache outcome header and generated/window timestamps.

## Health/ops

Provide `/health/live`, `/health/ready`, `/health/components`, `/metrics`, and a read-only reviewer operations/status API sufficient for the UI without leaking event bodies/secrets.

## Errors

Use `application/problem+json` fields:

- `type`
- `title`
- `status`
- `detail`
- `instance`
- `error_code`
- `request_id`

Dependency-specific raw exceptions must never be returned to clients.
