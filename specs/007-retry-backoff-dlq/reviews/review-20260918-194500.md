## Architecture and security review

- Mongo remains the canonical persistence boundary and is never acknowledged before insert or equivalent duplicate verification.
- Retry scheduling releases worker capacity through visibility deadlines.
- Permanent failures cannot create poison-message loops; unknown failures have a finite receive budget.
- DLQ diagnostic classification/reason values are allowlisted, message IDs are bounded printable ASCII, and event IDs are logged only after UUID validation.
- Retry/DLQ records contain message/event identity, attempt, safe code, classification, and delay only; arbitrary metadata and raw exception text are excluded.
- Consumer task failures are logged as `worker.supervision_failure` and re-raised after source preservation.
- The local queue/DLQ remains explicitly volatile; production SQS redrive is documented separately.
