# Security Hardening Checklist: Feature 017

**Purpose**: Verify abuse resistance, trust-boundary handling, safe diagnostics, and runtime least privilege.
**Created**: 2026-09-18
**Feature**: [spec.md](../spec.md)

## Input bounds

- [x] Body size is enforced before unbounded request parsing for declared and streamed bodies.
- [x] Feature 002 metadata limits remain authoritative and are tested through ingestion.
- [x] Query, search, date-range, page-size, cursor-size, and cursor-schema limits are explicit.
- [x] Search DSL is generated by the service and cannot be supplied by clients.

## Trust and browser boundary

- [x] CORS is exact-origin and disabled when not configured; wildcard and credential-bearing origins are rejected.
- [x] Forwarding headers remain untrusted at the default proxy-hop setting.
- [x] Security headers are emitted on normal and problem responses.

## Diagnostics and runtime

- [x] Startup/runtime diagnostics exclude secrets, body data, raw dependency messages, and stack traces.
- [x] Dependency timeouts are validated and bounded.
- [x] Application and UI container definitions use non-root runtime users.
- [x] Local Elasticsearch security assumptions are documented as local-only.

## Verification

- [x] Oversized input, CORS, forwarding spoof, redaction, metadata abuse, and security-header tests exist.
- [x] Full format, lint, type, unit, integration, failure, and diff checks are recorded.
