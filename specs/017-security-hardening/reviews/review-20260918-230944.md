# Feature 017 Review Gate

## Scope

Staff review and the comprehensive code, error, type, test, comment, and simplification reviews covered the receive-time HTTP limits, query and cursor validation, exact-origin CORS, proxy trust defaults, dependency timeouts, structured log redaction, problem responses, security headers, container users, and Feature 002 metadata boundary.

## Findings and disposition

| Finding | Disposition |
| --- | --- |
| Oversized body responses bypassed request correlation and completion telemetry | Closed. RequestIdMiddleware is registered outermost, so declared and streamed body rejections carry both correlation headers, security headers, metrics, and completion logs. |
| Credential-bearing Redis/Mongo URLs could appear in structured logs | Closed. The shared formatter strips URL userinfo, query, and fragment components for HTTP, Redis, MongoDB, and Unix URL schemes; unnamed LogRecords are handled safely. |
| Canonical event filters accepted control characters | Closed. EventQuery rejects control characters and DEL in event_type, user_id, and source_url. |
| Signed search cursors accepted extra keys or unsafe sort values | Closed. Decoding now requires the exact {"s": [...]} schema, two scalar sort values, finite numbers, and bounded strings. |
| CORS accepted malformed ports or a path suffix | Closed. Settings reject malformed/out-of-range ports and nonempty paths; empty configuration disables CORS. |
| Problem instances could echo arbitrary path identifiers | Closed. Problem, body-limit, and rate-limit responses use a bounded safe route instance. |
| Query strings could be unbounded before route parsing | Closed. The configurable 8 KiB default raw query limit returns a safe 414 before route dispatch. |
| Simplification review found two small duplicate validation/call sites | Advisory only. The current branches have distinct response semantics and stricter cursor checks; no correctness or maintainability gate remains. |
